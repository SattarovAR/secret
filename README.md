# Secret Spark

Минимальный self-hosted сервис для разовой передачи паролей, API-ключей и приватных заметок через Telegram или другой мессенджер.

## Возможности

- одноразовое чтение после явного нажатия кнопки;
- срок жизни ссылки: от 15 минут до 7 дней;
- досрочное удаление через отдельную ссылку управления;
- аудит даты создания, прочтения, истечения и удаления;
- шифрование содержимого в SQLite с AES-256-GCM;
- автоматическое удаление содержимого после чтения, отзыва или истечения;
- одна административная пара логин/пароль без регистраций и аккаунтов;
- собственная адаптивная веб-морда;
- HTTPS через Caddy.

Публичного REST API, отправки email, команд, ролей и интеграций нет.

## Как устроен доступ

- `/` и `/audit` защищены HTTP Basic Auth — здесь сотрудники создают ссылки и смотрят аудит;
- `/s/...` доступна без авторизации — эту ссылку отправляют получателю;
- `/manage/...` — секретная ссылка для проверки состояния и досрочного удаления.

Обычный `GET` не раскрывает содержимое. Поэтому генератор превью Telegram не уничтожит секрет: получатель должен явно нажать «Показать секрет», после чего браузер отправляет `POST`.

## Запуск

Требуются сервер с Docker, домен и открытые входящие порты `80` и `443`.

1. Направьте DNS-запись домена на IP сервера.
2. Создайте конфигурацию:

```bash
cp .env.example .env
openssl rand -base64 32
openssl rand -base64 24
```

3. Запишите полученные значения в `.env` как `SECRET_KEY` и `ADMIN_PASSWORD`, укажите свой `DOMAIN`.
4. Запустите сервис:

```bash
docker compose up -d --build
```

Caddy автоматически получит и будет обновлять TLS-сертификат. Приложение и SQLite не публикуются наружу напрямую.

## Обновление

```bash
git pull
docker compose up -d --build
```

## Резервное копирование

Данные находятся в Docker volume `secret_secret_data`. В базе хранятся зашифрованные активные секреты и метаданные аудита. После раскрытия, удаления или истечения поля с содержимым очищаются.

Отдельно и безопасно сохраните `SECRET_KEY`: без него активные секреты после восстановления базы расшифровать невозможно. Не коммитьте `.env` — он уже добавлен в `.gitignore`.

## Локальная разработка

Нужен Node.js 24 или новее. Сторонних npm-зависимостей нет.

```bash
npm test

PUBLIC_URL=http://localhost:3000 \
SECRET_KEY="$(openssl rand -base64 32)" \
ADMIN_USERNAME=team \
ADMIN_PASSWORD=local-development-password \
npm start
```

## Ограничения

- это инструмент разовой передачи, а не постоянный менеджер паролей;
- первый человек, получивший ссылку, может прочитать секрет;
- для особенно важных данных используйте короткий TTL и передавайте ссылку через доверенный канал;
- сервис передаёт только текст, не файлы.
